## Roles, leadership, team (Ch 4–5)
**Who is responsible? (📘)** — Accepts or requests changes to increments → **PO**; servant leader removing barriers → **SM**; provides due dates → **PO**; manages backlog by business value → **PO**; big picture of value, time, budget → **Project Sponsor**; writes acceptance tests → **Development Team**; helps team self-govern → **SM**; demonstrates increment in review → **Development Team**; facilitates meetings → **SM**.

**Leadership or management? (📘)** — Planning workshops **L**; Gantt charts **M**; team brainstorming **L**; career planning **L**; HR management **M**; team time tracking **M**; team member recognition **L**; task assignment **M**.

**Servant leadership or command-and-control? (📘)** — Suggestions box **SL**; Gantt chart on wall **C&C**; detailed task lists **C&C**; creating whole WBS alone over a weekend **C&C**; admin work for team members **SL**.

**Match: team stage ↔ leadership style (📘)** — Forming ↔ **Directing**; Storming ↔ **Coaching**; Norming ↔ **Supporting**; Performing ↔ **Delegating**.

**Conflict level (📘)** — "You never care how it impacts anyone else!" **Level 3**; "We'd be better off without them!" **Level 4**; "You and me, outside, right now!" **Level 5**; "How do I request a ticket again?" **Level 1**; "I'll have extra work too if we go with your method" **Level 2**.

**Match: tool → description (📘)** — Last responsible moment ↔ deciding when you have the most information; Iterations and feedback ↔ delivering in increments so features can be evaluated while more are built; Refactoring ↔ making code readable/maintainable without changing behaviour; Self-determination, motivation, leadership expertise ↔ deciding which work will be done without external approval.

| Y-axis of a burndown chart: story ____ | **Points** |
| Chart tracking work left | **Burndown** |

| Agile planning tool | **Task board** |
| ____ diagrams are used to determine the root cause of issues | **Fishbone** |

**Match: tool or technique (📘)** — Risk-based spike ↔ experiment on a specific threat; Ideal time ↔ estimate assuming no interruptions; Backlog refinement ↔ review, re-estimate, re-prioritise; Risk-adjusted backlog ↔ backlog including problems and threats; Progressive elaboration ↔ update an artifact as more is known; Planning poker ↔ card game to agree estimates; Risk burndown graph ↔ daily estimated impact of threats; Pre-mortem ↔ imagine failure, find causes; User story ↔ minimal feature description of who and why.

**Match: tool or technique 2 (📘)** — Definition of Done ↔ agreed condition meaning a feature is complete; Task board ↔ visualise progress of items through an iteration; MVP ↔ small feature to learn customer behaviour (learning); Exploratory testing ↔ verify whether an approach will work; MMF ↔ small self-contained feature delivering value (earning); Usability testing ↔ customers use the product to find operating problems; Technical debt ↔ work to make code maintainable long-term; Backlog grooming ↔ add, remove, reprioritise features; Infrastructure work ↔ hardware, networking, equipment, facilities.

**Match: retrospective comments (📘)** — "Velocity is the SM's job" → **Not constructive**; "Commit to more points than last sprint" → **Stop doing**; "I like planning poker" → **Continue doing**; "PO could wait to talk to stakeholders until after the sprint backlog is agreed" → **Start doing**.

**Common or special cause? (📘)** — Waiting for Sameer again **Common**; Vaishali got married **Common**; inspector caught malaria **Special**; paint shop a day behind again **Common**; design late, done today (two versions) **Special** / **Common**; estimates 5% too high on average **Common**.

**Standup statements (📘)** — Valid: trip not approved; finished supercharger; finished testing launcher; PC needs RAM; stuck on nose cone. Invalid: "add a turbo booster"; personal date remark; "thread it backwards" (problem-solving).

**Standup do's/don'ts (📘)** — Do: attend if you have a task; only task-holders talk; speak to team; new sticky per new task. Don't: side conversations; discuss issues; solve problems.

**V&V associated? (📘)** — Associated: build server, refactor, TDD, ATDD, automated build, fast failure, TFD, pair programming. Not associated: WIP, TED, velocity, SME, relative sizing, EI, servant leader, ROI.

**XP term or made up? (📘)** — XP: iteration, sustainable pace, courage, simplicity, refactoring. Made up: continuous interpretation, pear programming, sample design, small revisions, passion, execution game, remarketing, architectural spoke, complexity.
